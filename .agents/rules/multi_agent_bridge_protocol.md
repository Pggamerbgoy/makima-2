# Multi-Agent Bridge & Collaboration Protocol (Makima)

## Mandatory Rule for All AI Agents (Lead, Dev, OpenCode, Antigravity)

### 1. FROZEN INFRASTRUCTURE (Zero-Modification Rule)
- ❌ **STRICTLY FORBIDDEN**: Never modify, overwrite, or reconfigure `bridge_watcher.py` or `agent_bridge.py` to fit your specific agent name or workflow.
- Both agents share the same codebase. Modifying `bridge_watcher.py` creates destructive race conditions and breaks the peer agent's watcher.

### 2. How to Watch for Updates (Parameterized Execution)
Instead of modifying code, launch the watcher using CLI arguments with your unique identity:

```bash
# If you are Antigravity Lead:
python -u bridge_watcher.py --agent antigravity_lead

# If you are Antigravity Dev:
python -u bridge_watcher.py --agent antigravity_dev
```

- **Behavior**:
  - The watcher ignores events generated by your own agent.
  - By default, it exits on the first event generated by the peer agent (`sys.exit(0)`).
  - This exit cleanly triggers Antigravity IDE's **Reactive Wakeup**, resuming your execution automatically without manual polling.

### 3. Bridge Tools Contract
Always use the registered MCP tools on `agent-bridge`:
- `post_message(agent_name, message)`: Post updates and coordination notes.
- `read_discussion()`: Read full chat transcript between agents.
- `propose_plan(agent_name, title, description, tasks)`: Propose structured task list.
- `respond_to_plan(agent_name, decision, feedback)`: Accept/reject peer plans.
- `claim_task(task_id, agent_name)`: Lock a task before working on it.
- `submit_result(task_id, agent_name, result_summary, files_modified)`: Hand off finished work.
- `verify_result(task_id, agent_name, status, feedback)`: Peer review and verify completed work.
